## Hooks Context

The event table below describes Claude Code. Codex and Grok use
`native-hook.ts`; see `docs/harness-adapters.md` for their contracts. Reuse shared
decisions, translate payloads and responses, and test actual stdin/stdout. Never
parse another host's transcript as Claude JSONL. Grok reads only PreToolUse
`additionalContext`; Codex native hooks require trust. Registration alone does not
prove execution.

### Shebang Gotcha (Windows / Reduced PATH)

| Shebang | Works | Alternative |
|---------|-------|-------------|
| `#!/usr/bin/env bash` | NO | `#!/bin/bash` (absolute path) |
| `#!/usr/bin/env bun` | YES | Poneglyph includes bun in PATH via the generated user settings (`settings.global.json` + machine overlay) |
| `#!/bin/bash` | YES | Absolute path, does not depend on env |

**Prefer `.ts` with bun** over `.sh`. If `.sh` is needed, use `#!/bin/bash`.

### Available Hook Events + reliability

Reliability matters because PreToolUse/PostToolUse may silently fail to fire (open issue #6305); never use them as the *sole* gate for a critical check.

Hook logs (`learnedLog()`) live in `<project>/.claude/learned/` only when the project git-ignores that path; otherwise they fall back to `~/.claude/learned/<project>/`, so every `<project>/.claude/learned/` below means that resolved folder.

| Event | When | Reliability | Usage in Poneglyph |
|-------|------|-------------|--------------------|
| PreToolUse | Before tool | Unreliable (#6305) | Six handlers, all silent unless they fire; the first four match `Bash`. (1) `headless-model-gate.ts`, denies a `claude -p`/`--print` without `--model`, or with a Fable/Opus model (`--model`/`--fallback-model`) and no `--allow-expensive`, and a repo headless script (`evals/run.ts`, `compare.ts`, `probe-activation.ts`) with an expensive `--model`; the braces are `scripts/lib/headless.ts`. Cause: one day ran 82 headless sessions, 44 Opus + 29 Fable. (2) `bash-output-shaper.ts`, **deny** a `cat`/`sed -n` on a file >12 KB (Read with offset/limit, or Grep), **rewrite** an unbounded `git log` → `--oneline -n 30` and `ls -R`/`find`/`tree` → `\| head -n 200` via `updatedInput`; never touches tests, `git diff`, piped or redirected commands, or a line ending `# raw`. Cause: tool output was 56 % of context over 14 days, `cat` its heaviest file family. (3) `remote-git-gate.ts` (also matches `PowerShell` and `Monitor`), denies `git push`, `gh pr create` and `gh pr merge` unless this turn asked for them: an order in the prompt (accents, clitics and dictation folded), a reply that opens with assent to an offer of the action, or an `AskUserQuestion` answer that names it. A PR ask covers its push and a merge ask its PR; a force push always needs the words. Quoted, pasted and question spans never count. Fails closed on its own errors; logic in `hooks/lib/remote-git.ts`. (4) `design-file-hint.ts` (matcher `Edit\|Write\|MultiEdit\|Bash`), on the first contact with a UI file (`.html .css .scss .tsx .jsx .vue .svelte`) in a session, either an edit tool's `file_path` or a path token in a Bash command (search filters such as `--include=*.tsx` or `-name '*.vue'` are patterns, not files) (headless agents edit with `sed -i` or a heredoc, and a read counts too), adds a factual `additionalContext` note: the design file in use, or none found plus how the extraction offer reaches the user (the host's question tool); never blocks. One line in `<project>/.claude/learned/design-file-hints.log` is both the log and the once-per-session marker; the project is `CLAUDE_PROJECT_DIR`, because the payload `cwd` follows the agent's `cd`. Codex gets the same note through `native-hook.ts` on `apply_patch`; Grok is not wired. Cause: skill text alone never produced the offer, because the skill and its reference often do not load. (5) `router/agent-hooks.ts` (matcher `Agent`), when the main model launches the `prompt-router` subagent, rewrites its task via `updatedInput`: the project's catalog skills its agent file lacks (usually none), the task in `<prompt>`, then the `<past>` memory. Any Agent task that runs on Haiku (call `model`, then the agent file, then `CLAUDE_CODE_SUBAGENT_MODEL`, which Explore and Plan ignore: they inherit the parent's model), the router's included, gets the Haiku budget line from `lib/haiku-budget.ts` appended (work in cycles: it announces compaction near 90k, measured below at 87k; 10k of headroom for untrimmed tool results, Reads in batches, keep using tools after a compaction, final answer under 5k tokens). The glossary and user-level catalog are baked into `<config>/agents/prompt-router.md` by sync-claude, so they stay in the cached system prompt (a catalog in the task cost ~3x). Not SubagentStart: an `additionalContext` over ~10 KB reaches the agent as a 2 KB preview of a saved file, while a 60 KB task arrives whole. (6) `haiku-context-brake.ts` (matcher `Read`), inside a subagent (`agent_id`) on Haiku, reads the last request of `<main transcript stem>/subagents/agent-<id>.jsonl`; when a Read's estimate (bytes / 2 of the lines it returns) would carry the context past 90k, counting tool results not yet followed by a request (the current request may not be written yet), or the host would reject it (over 0.9 × its Read token cap, or no `limit` on a file over 256 KB), it cuts the Read's `limit` to the lines that fit via `updatedInput`, with an `additionalContext` note to continue from the next line. Only when fewer than 20 lines fit is the Read denied, with a reason asking for Grep or an answer that opens with `INCOMPLETE: context budget reached.` and ends with `Left unchecked:`. No hard stop: Haiku compacts near 87k (`modelSettings["claude-haiku-5-5"].autoCompactWindow` = 120k, which reaches subagents in sessions started after it), and compaction runs between requests, so the hook only keeps one Read from jumping past it. Log: `<project>/.claude/learned/haiku-brake.log` (`narrow`, `read`, or `miss` when the transcript is not found). Cause: Haiku bills a prompt over 100k at 5x, and 13 % of 14 days of Haiku subagent requests passed it |

> **Stdout contract (CC ≥2.1.248)**: a stdout that starts with `{` and ends with `}` but is not valid JSON is now a reported hook error, not plain text. `security-gate.ts` prints one `JSON.stringify` object; `skill-activation.ts` prints prose that never starts with `{`.

There is no automatic test-pass validator; the main session verifies tests after each build step (a Stop test-gate was declined). Never rely solely on PostToolUse for security enforcement.

> **Stop / SubagentStop feedback** (CC ≥2.1.163): both can return `hookSpecificOutput.additionalContext` to feed Claude and keep the turn going without being flagged a hook error. The security gate uses BOTH channels: `systemMessage` for the user + `additionalContext` instructing the model to verify/redact in-turn.
